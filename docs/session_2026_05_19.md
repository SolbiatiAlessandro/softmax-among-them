### Symptoms

```bash
curl -H "X-Auth-Token: <TOKEN>" https://softmax.com/api/observatory/whoami
# {"subject_type":"anonymous",...}  ← token accepted but treated as anonymous

curl -H "X-Auth-Token: <TOKEN>" https://softmax.com/api/observatory/v2/leagues
# {"detail":"Failed to authenticate"}  ← 401
```

### Root Cause
The token `6PnHPiX9SWLBZhkMyHr4JJWKuUWZY29t_2CTrVDICHs` is expired
server-side. It was valid in session 2026-05-12 but Softmax sessions expire.
The whoami endpoint returns HTTP 200 with `subject_type: anonymous` — meaning
the server processes the request but sees it as an unauthenticated session.
All authenticated endpoints (leagues, upload, submit) return 401.

## Policy: lessandro-kensho

### Strategy
Based on `evidencebot_v2` from the BitWorld repo — the strongest available
reference bot (5010 lines of Nim). Key capabilities:

**Crewmate behavior:**
- Full-map localization using patch-hash voting (3-tier: local search → patch
  voting → spiral fallback)
- A* pathfinding with momentum-aware steering and anti-stuck jiggling
- Task detection via radar dots and task icons in 128×128 frames
- Evidence-only voting: only votes when it has firsthand visual evidence
- Eager checkout: marks tasks resolved as soon as inspection area clears
  (v2 improvement over v1 that waited `TaskIconMissThreshold` frames)
- Radar gate removed (v2): navigates to radar targets without waiting for
  task icon confirmation

**Imposter behavior:**
- Kill detection via kill button icon visibility
- Self-report after kills (v2 improvement): imposter reports its own kill within
  `ImposterSelfReportRecentTicks=30` ticks to pre-empt other reporters
- Central-room stuck detection (v2): detects endgame gather stalls and escapes
- Fake task behavior (navigates to task areas without completing)
- Accusation strategy in voting chat

## Game Mechanics (Confirmed from Source)

| Parameter | Value |
|-----------|-------|
| Players | 8 (fixed) |
| Imposters | 2 |
| Tasks per crewmate | 8 |
| Kill cooldown | 900 ticks |
| Vote timer | 6000 ticks |
| Start wait | 120 ticks |
| Role reveal | 120 ticks |
| Max ticks | 10000 |
| Frame resolution | 128×128 pixels |
| Frame encoding | 4-bit packed, PICO-8 16-color palette |
| Action protocol | Bitscreen v1 (WebSocket binary frames) |
| Score schema | `scores[]`, `win[]`, `tasks[]`, `kills[]` per slot |

### Score Optimization
Crew win conditions (crewmate perspective):
1. Complete all tasks before time runs out
2. Vote out all imposters

Imposter win conditions:
1. Kill enough crew to reach parity (4 crew = 2 imposters → imposter wins)
2. Survive until `maxTicks`

**Key insight**: `evidencebot_v2`'s imposter self-report is a major strategic
advantage. By reporting your own kill before any crewmate can, you establish a
false alibi ("I found the body") and can deflect suspicion to others.

## LLM Enhancement Path (Future Work)

The `SMART_BOT_GUIDE.md` in the bitworld repo describes adding LLM strategic
reasoning on top of the perception pipeline. This would create a significantly
stronger `lessandro-bodhi` policy.

Architecture: Nim bot (perception + action) + Python sidecar (LLM reasoning)

Key design:
1. Nim bot exports game state as JSON snapshot each tick
2. Python sidecar receives snapshots via socket
3. On key events (body found, meeting called, kill opportunity), queries LLM
4. LLM returns directive (strategy, vote target, chat message)
5. Nim bot executes directive

Implementation requires:
- Socket communication between Nim and Python
- Three-tier memory system (working/episodic/strategic)
- LLM prompts for crewmate and imposter roles
- Docker image with both processes

With the OpenRouter API key (provided separately by the user):

```bash
  --name lessandro-bodhi \
  --secret-env OPENROUTER_API_KEY=<openrouter-key>
```
