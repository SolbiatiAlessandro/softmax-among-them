### 2. Anonymous token cannot upload policies (API change since 2026-05-12)

The `/stats/policies/submit/presigned-url` endpoint now returns 401 for the
anonymous token. Previously (2026-05-12 23:06) it allowed uploads from anonymous
tokens.

The softmax.com/api/validate endpoint confirms the token is INVALID:
```bash
curl -s -H "Authorization: Bearer <token>" "https://softmax.com/api/validate"
# → {"valid":false,"error":"Invalid or expired token"}
```

The observatory API /whoami accepts the token but returns anonymous:
```bash
curl -s -H "Authorization: Bearer <token>" "https://api.observatory.softmax-research.net/whoami"
# → {"user_email":"unknown","subject_type":"anonymous",...}
```

**Root cause**: The token is not a valid user-authenticated token. It was stored
in both `login_tokens` and `user_tokens` in `~/.metta/cogames.yaml` but is not
linked to a GitHub account.

**Fix for next session**: Log in via `cogames auth login` and follow the browser
GitHub OAuth flow to get a properly authenticated token. The login URL is:
```
https://softmax.com/cli-login
```

### 3. V2 Coworld system discovered but requires proper auth

The v2 system is at `api.observatory.softmax-research.net/v2/`. Key endpoints:

| Endpoint | Auth Required |
|----------|---------------|
| `GET /v2/coworlds` | BearerAuth (must be non-anonymous) |
| `GET /v2/coworlds/{coworld_id}` | **Public (no auth!)** |
| `POST /v2/coworlds/upload` | BearerAuth |
| `POST /v2/container_images/upload` | BearerAuth |
| `POST /v2/coworlds/play/session` | BearerAuth |
| `GET /v2/coworlds/play/session/{session_id}` | **Public** |
| `POST /v2/coworlds/play/session/{session_id}/join` | Optional auth |

Once the coworld ID for Among Them Daily is known (format: `cow_<uuid>`), the
manifest can be fetched without auth:
```bash
curl -s "https://api.observatory.softmax-research.net/v2/coworlds/cow_<uuid>"
```

**How to find the coworld ID**: Need authenticated access to `GET /v2/coworlds`.
The `coworld` CLI from the Metta repo uses `uv run coworld leagues` to list them.

### 4. `coworld` CLI requires Metta repository checkout

The `play_amongthem.md` guide uses `uv run coworld` which is only available from
within the Metta project directory (`uv run` executes project entry points). The
`coworld` package is NOT published to PyPI.

**Metta GitHub**: `Metta-AI` organization.

**Alternative**: The v2 API can be called directly via curl/httpx once you have
a valid user token.

### 5. `select` button removed from trainable action set

Since mettagrid 0.26.19+, `select` is no longer in `BITWORLD_ACTION_NAMES`.
Calling `bitworld_action_index(encode_buttons(("select",)))` raises `ValueError`.

**Fix applied**: Both `lessandro-dharma` and `lessandro-karma` now use `b` button
instead of `select`:
```python
_SELECT = bitworld_action_index(encode_buttons(("b",)))
```

Note: It's unclear if `b` actually triggers voting/reporting in Among Them.
The trainable actions are: noop, a, b, up, down, left, right (and diagonals + a/b).

## New Policy: lessandro-karma

### Strategy
Improved policy using sprite_player observation (richer game state).
Automatically detects observation mode (sprite_player vs pixels).

**Sprite-player mode** (1231 features — preferred):
1. **Crewmate** (kill_icon == 0):
   - Move toward visible task icons; press A when within interact radius
   - Follow task arrows for off-screen tasks
   - Exploration spiral when no tasks visible
2. **Imposter** (kill_icon > 0):
   - Hunt nearest alive player visible on screen
   - Press A when within kill radius AND kill ready (kill_icon == 255)
   - Explore when no targets visible

**Pixel mode** (65536 features — fallback):
   - Same heuristic as `lessandro-dharma` (task-color seeking)

### Observation layout (sprite_player)
```
obs[0]     = phase  (0=lobby, 1=playing, 2=voting, 3=vote_result, 4=game_over, 5=role_reveal)
obs[1]     = kill_icon (0=crewmate OR no kill, 1=imposter cooling, 255=imposter ready)
obs[2]     = task_progress (0-255 = 0-100%)
obs[3]     = tasks_remaining (count)
obs[4..1028) = map grid 32×32 tiles (PICO-8 color each)
obs[1028..1092) = 16 player slots × 4 features [x, y, color, flags]
obs[1092..1156) = 16 body slots × 4 features [x, y, color, 1]
obs[1156..1231) = 15 task slots × 5 features [icon_x, icon_y, arrow_x, arrow_y, flags]
```

Task slot flags: `ICON_VISIBLE=1`, `ARROW_VISIBLE=2`
Player slot flags: `PRESENT=1`, `ALIVE=4`, `FLIP_H=16`, `GHOST=32`

## V2 Coworld workflow (for next session with valid token)

Once proper GitHub OAuth is complete:

```bash
# 1. List available coworlds
curl -H "Authorization: Bearer <TOKEN>" \
  "https://api.observatory.softmax-research.net/v2/coworlds"

# 2. Get Among Them manifest (once coworld_id known)
curl "https://api.observatory.softmax-research.net/v2/coworlds/cow_<uuid>"

# 3. Build Docker image (policy in a container)
docker build --platform=linux/amd64 -t lessandro-karma:latest .

# 4. Upload Docker image (get ECR credentials)
curl -H "Authorization: Bearer <TOKEN>" \
  -X POST -H "Content-Type: application/json" \
  -d '{"name": "lessandro-karma"}' \
  "https://api.observatory.softmax-research.net/v2/container_images/upload"
# → returns EcrPushInfo with ECR registry/repo/tag/credentials

# 5. Push Docker image to ECR using returned credentials
# 6. Complete upload
curl -H "Authorization: Bearer <TOKEN>" \
  -X POST -H "Content-Type: application/json" \
  -d '{"id": "img_<uuid>"}' \
  "https://api.observatory.softmax-research.net/v2/container_images/upload/complete"

# 7. Submit via the Among Them Daily league page at:
#    https://softmax.com/observatory/v2
```
