## Key Technical Discovery: sprite_player Observations

The most important finding of this session: Among Them supports **sprite_player observations**,
a 1231-dimensional structured vector far richer than raw pixels.

### Observation Layout (SPRITE_PLAYER_FEATURES = 1231)

```
[0]         phase             LOBBY=0, PLAYING=1, VOTING=2, VOTE_RESULT=3, GAME_OVER=4, ROLE_REVEAL=5
[1]         kill_icon         0=crewmate, 1=imposter-on-cooldown, 255=imposter-kill-ready
[2]         task_progress     0-255 scaled percentage of all tasks complete
[3]         tasks_remaining   count of tasks left for me
[4:1028]    map grid          32×32 cells, PICO-8 colour at each (1024 bytes)
[1028:1092] player slots      16 players × 4 bytes: x, y, colour, flags
                              flags: PRESENT=1, ALIVE=4, FLIP_H=16, GHOST=32
[1092:1156] body slots        16 bodies × 4 bytes: x, y, colour, 1
[1156:1231] task slots        15 tasks × 5 bytes: icon_x, icon_y, arrow_x, arrow_y, flags
                              flags: TASK_ICON_VISIBLE=1, TASK_ARROW_VISIBLE=2
```

### Coordinate System
- Screen is 128×128 pixels
- Screen centre is (64, 64) — our player is always here
- Player positions: raw screen coords +1 (so 0 means absent). Player at screen (63,63) → obs (64,64)
- Task positions: raw screen coords (0-127 range expected, clamped to uint8)
- x increases right, y increases down (standard screen coords)

### How to Detect Observation Mode in step_batch
```python
# In _choose_actions(raw_observations):
flat = raw_observations.reshape(batch_size, -1)
total_feats = flat.shape[1]
is_sprite = (total_feats % SPRITE_PLAYER_FEATURES == 0) and (raw_observations.ndim <= 2)
```

For sprite_player leagues, `raw_observations` will be `(batch, 1231)` (frame_stack=1) or 
`(batch, 2462)` for frame_stack=2. For pixel leagues, `raw_observations` is `(batch, 4, 128, 128)`.

## Policy: lessandro-anatta

### Strategy

**PLAYING — Crewmate (kill_icon == 0):**
1. Find nearest visible task arrow/bubble in observation slots [1156:1231]
2. Navigate toward the arrow/bubble using (arrow_x - 64, arrow_y - 64) as direction vector
3. If target is within ±18px of screen centre, press A (interact/complete task)
4. If no task visible, do deterministic exploration spiral (offset by agent_id)

**PLAYING — Imposter (kill_icon > 0):**
- `kill_icon == 255` (kill ready): hunt nearest alive non-ghost player, press A when in range
- `kill_icon == 1` (on cooldown): fake crewmate behavior (seek tasks but don't interact)

**VOTING:** Move UP for 20 ticks, press A for 20 ticks (attempts to vote skip), then noop

**ROLE_REVEAL / LOBBY:** Press A every 30 ticks (advance animation / join)

**VOTE_RESULT / GAME_OVER:** Press A every 60 ticks (advance screen)

**Pixel fallback (if not sprite_player):** Same as lessandro-dharma (colour-heuristic)

## Known Issues / Unknowns

### 1. Voting UI Layout Unknown
During VOTING phase, we don't know exactly where the SKIP button is. The current 
strategy (move up, press A) is a guess. If the skip button is elsewhere, we might 
accidentally vote for a player. Need replay data to diagnose.

### 2. Task Coordinate Calibration Needed
Task position coordinates are assumed to be screen-space (0-127). This needs 
verification from actual game replays. The arrow direction heuristic (arrow_x - 64)
should work if screen centre is (64, 64).

### 3. Self-player Detection
We skip players at (64, 64) assuming that's our avatar. Due to the +1 offset in
player positions, our avatar at screen (63, 63) maps to obs (64, 64). This should
be correct but needs replay verification.

### 4. Kill Action Verification
When imposter kill is ready, pressing A near a player should kill them. Unclear if 
it's A or B or a special action. Monitor kill counts in match artifacts.
