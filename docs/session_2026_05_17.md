## Key Discovery: sprite_player Observation Mode

The `mettagrid.bitworld_sprite_player` module exposes a **sprite_player**
observation format that delivers structured game state instead of raw pixels.

### Observation layout (SPRITE_PLAYER_FEATURES = 1231 bytes per frame)

| Bytes | Content |
|-------|---------|
| 0 | Phase: 0=lobby, 1=playing, 2=voting, 3=vote_result, 4=game_over, 5=role_reveal |
| 1 | Kill icon: 0=no, 1=cooldown, **255=kill ready → I am imposter!** |
| 2 | Task progress bar (0-255) |
| 3 | Tasks remaining counter |
| 4–1027 | 32×32 map grid (camera-relative tile color indices) |
| 1028–1091 | 16 player slots × 4 bytes: x+1, y+1, color, flags |
| 1092–1155 | 16 body slots × 4 bytes: x+1, y+1, color, present |
| 1156–1230 | 15 task slots × 5 bytes: icon_x, icon_y, arrow_x, arrow_y, flags |

### Player flags
- `SPRITE_PLAYER_FLAG_PLAYER_PRESENT = 1`
- `SPRITE_PLAYER_FLAG_PLAYER_ALIVE = 4`
- `SPRITE_PLAYER_FLAG_PLAYER_GHOST = 32`

### Task flags
- `SPRITE_PLAYER_FLAG_TASK_ICON_VISIBLE = 1` → task icon on screen
- `SPRITE_PLAYER_FLAG_TASK_ARROW_VISIBLE = 2` → arrow pointing to off-screen task

### How to declare sprite_player mode from your policy

The runner reads `policy.policy_env_info.observation_kind` to decide which
WebSocket endpoint to use (`/player` = pixels, `/sprite_player` = structured).

To declare sprite_player mode, override the `policy_env_info` property to
return a `PolicyEnvInterface` with `observation_kind="sprite_player"`:

```python
import gymnasium as gym
from mettagrid.bitworld import BITWORLD_ACTION_COUNT, BITWORLD_ACTION_NAMES
from mettagrid.bitworld_sprite_player import SPRITE_PLAYER_FEATURES
from mettagrid.policy.policy import MultiAgentPolicy
from mettagrid.policy.policy_env_interface import PolicyEnvInterface

FRAME_STACK = 4

class MyPolicy(MultiAgentPolicy):
    def __init__(self, policy_env_info: PolicyEnvInterface, device="cpu"):
        super().__init__(policy_env_info, device=device)
        obs_space = gym.spaces.Box(0, 255, (FRAME_STACK * SPRITE_PLAYER_FEATURES,), dtype=np.uint8)
        act_space = gym.spaces.Discrete(BITWORLD_ACTION_COUNT)
        self._sprite_env = PolicyEnvInterface.from_spaces(
            observation_space=obs_space,
            action_space=act_space,
            num_agents=policy_env_info.num_agents,
            action_names=list(BITWORLD_ACTION_NAMES),
            observation_kind="sprite_player",
        )

    @property
    def policy_env_info(self) -> PolicyEnvInterface:
        return self._sprite_env

    def step_batch(self, raw_observations, raw_actions):
        # raw_observations.shape = (8, FRAME_STACK * SPRITE_PLAYER_FEATURES)
        last_frame = raw_observations[:, -SPRITE_PLAYER_FEATURES:]  # (8, 1231)
        ...
```

## Key Discovery: SELECT Not in Trainable Action Set

The `BITWORLD_ACTION_NAMES` only includes directions (noop/up/down/left/right/
up-left/up-right/down-left/down-right) × (none/a/b). **SELECT (mask=16) is
NOT a valid action.**

```python
# WRONG: raises ValueError
_SELECT = bitworld_action_index(encode_buttons(("select",)))

# Correct during voting: use A to vote, B to skip/report
```

The previous session's `lessandro-dharma` policy had this bug; it imported
`_SELECT` which would raise on import. That's why it failed in the worker.

## Policy: lessandro-nirvana (v1)

**File:** `lessandro_nirvana_policy.py`  
**Bundle:** `lessandro_nirvana_bundle.zip`  
**Class:** `lessandro_nirvana_policy.NirvanaPolicy`

### Strategy

1. **Phase detection**: lobby → wait; voting → dpad + A/B; game_over → A to advance
2. **Role detection**: `kill_icon == 255` → imposter with kill ready
3. **Crewmate task completion**:
   - Navigate toward nearest task icon on screen (move toward it, press A)
   - When > 22px away: move
   - When 10–22px: alternate move+A and pure A
   - When < 10px: always press A
   - If no icon visible: follow task arrow direction
4. **Imposter kill**:
   - Find nearest alive player > 6px from center (to exclude self)
   - Move toward them; press A when within 22px
5. **Body reporting**: press B when body is within 22px
6. **Exploration**: 12-step spiral (right×3, down×3, left×3, up×3) at 6 ticks/step
